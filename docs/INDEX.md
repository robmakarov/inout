# docs/ — agent playbooks, one per instrument. Open the one your task names. Nothing here is for humans; current truth only, rewrite on change.
- FLAGS.md — every URL / sticky switch and its default with the measured effect; rewrite the row when a default moves.
- TAKE_REPORT.md — read a take's report card off Robert's machine (`__inoutReport()` family); the twelve dimensions, the editor's own card (`__inoutEditorReport()`), and what the card does not claim.
- SCREEN_WEDGE.md — Chrome's screen picker never settling on macOS: the playbook, the verdict table, what is ruled out, the standing second-origin test, Robert's levers.
- CRASH_BOUND.md — `scripts/crash-bound.mjs`: kill Chrome mid-take; the salvage bound and the first-seconds floors (H2/H2b).
- MEMORY_SLOPE.md — `scripts/memory-slope.mjs`: hour-scale RSS/heap slope, read from halves (H3); `--real` is the max60 cell, because the synthetic source crashes the tab there (G8).
- AI_EXPORT.md — the For-AI PDF spec (AI1): index page, delta keyframes, budgets, reader limits; the event-sidecar schema (AI2).
- QA_MATRIX.md — `scripts/browser-check.mjs` gates per browser; evidence in docs/qa/*.json.
- RU_REACHABILITY.md — `scripts/ru-reachability.mjs`: DNS / TLS / block-page checks from RU networks; the risk ranking.
- CLOUD_SETUP.md, CLOUD_RESET.md — provisioning and wiping the Supabase project (phase 2).
- `scripts/x14a-stamps.mjs` (X14a, no doc of its own — the header is the playbook) — does the media carry its own capture stamp? Per-source table of `VideoFrame.metadata()`, `metadata().captureTime`, `VideoFrame.timestamp` and `AudioData.timestamp` against read time, the drift over a 120 s run, and the line that matters: what the platform REPORTS as input latency against what the delay MEASURES. `--rung=floor` asks the degraded request; `--fake` substitutes devices and labels the rows. **Never add `--use-fake-ui-for-media-stream` to a getDisplayMedia launch** — it answers the surface picker with nothing and every request returns NotReadableError (the rig runs two passes for exactly this reason).
- `scripts/b13-tabaudio.mjs` (B13) — plays a known 12-tone signal in the page, records it through the product's own tab-audio path, and reports four spectra (reference / opus floor / captured channel / exported file), the stereo markers, the delivered ec-ns-agc as the TAKE recorded them, and the anchor both ways (`--looplat=both`). `--rung=floor` reproduces the degraded request a wedged machine makes, which is where the bass goes. It shims `getDisplayMedia` to pick the current tab (the app asks to EXCLUDE its own tab, so nothing could answer the picker otherwise) and passes the app's audio constraints through untouched. `--mute-audio` would silence the loopback itself, so local playback is suppressed on the constraint instead.
- `scripts/g7-lateness.mjs` (G7, no doc of its own — the header is the playbook) — the main-thread lateness instrument's own rig, four lanes. `clamp` is the design's evidence and the only rig in this repo that launches Chrome with background throttling LEFT ON (`throttled: true` in scripts/lib/chrome.mjs): it runs a main-thread ticker and a worker beat in the SAME hidden page, which is what a take is. `cost` runs a fixed-wall workload with and without a sampler, alternating, in one page load. `take` records through the product and reads the `lateness` dimension off `__inoutReport()`. `drag` drives the timeline drag through the editor's own 15 s window — B10's stalls are DRAG stalls, and the editor lane alone does not reproduce them.
- `scripts/dpip-check.mjs` (U1, no doc of its own — the header is the playbook) — the on-top recorder panel. Four one-click cases answer who may spend the record press's transient activation (`plain`, `microtask`, `afterDisplay`, `panelFirst`, `pickerAlive`, `noActivation`); `--app` drives the DEPLOYED build end to end — press record, panel opens, timer advances, Pause/Continue, Stop from the panel — and prints GREEN/RED. `--nopause` keeps the panel open and never presses it, which is the run to read against a `?panel=0` control. Automation cannot measure the window's minimum size: Chrome ignores the requested size under CDP and reports outer 0x0 or the opener's box, so the floor only comes from a real drag (`__inoutPanel()` collects and persists it).
- `scripts/b13-noise.mjs` (B13(3)) — points at any file ffmpeg can decode and answers "what is in here that should not be": 1 ms event detection against the run's own median (for the tone signal; percussion in program material sets it off by design), and THD+N — everything that is NOT one of the twelve tones, which is the measurement B13's first pass could not make because it only ever read the tone levels, and neither a limiter nor a resampler moves those. `--program` switches to octave-band shape against the reference.
- `scripts/safari.mjs` (P9, no doc of its own — the header is the playbook) — runs one JS file inside Robert's REAL Safari through safaridriver and prints what it returns. Playwright's WebKit is NOT Safari (no hardware-codec parity), which is why three tasks were blocked on an artifact; this is the actual browser on the actual machine. `?synthetic=1` needs no permission, so every capability question is answerable unattended — a real screen or camera take still needs Robert's hands, because WebDriver cannot click a native picker. One-time setup, already done: Safari → Settings → Developer → "Allow remote automation".
- `scripts/see.mjs` (no doc of its own — the header is the playbook) — a picture of any URL from a REAL Chrome, pane or no pane: PNG + one JS expression + the console, ~4 s steady (the first launch of the day is slower), background throttling off, throwaway profile so it never tests the PWA's old build. Headless by default; `--headed` when the GPU path matters. The global pane-guard hook (`~/.claude/hooks/pane-guard.py`) refuses a pane screenshot while the pane is hidden and points here.
- `scripts/b13-signal.mjs` — the signal both B13 rigs use, as source text, so the thing the page PLAYS and the thing the analyser calls the REFERENCE are one object and cannot drift. `buildSignal` = the twelve-tone ruler; `buildProgram` = eight seconds of chords, kick and hats, which is what gets listened to.
- `scripts/e3-claimpace.mjs` (E3, no doc of its own — the header is the playbook) — what does a CLAIMED background render still obey? Records a take, makes a pixel edit so J5 starts a render, presses Export 2.5 s later so the press JOINS the running job, and times press → file twice: once with a pointer moving over the editor at pointer cadence (what a person watching the dock does), once with the hand off it. The delta is the brake still riding a job somebody is waiting for. `--lane=hand|still` runs one side.
- `scripts/e3-laneart.mjs` (E3, no doc of its own — the header is the playbook) — is the timeline's lane art racing the at-stop pre-render? Times the editor's first seconds twice — default, and `?prerender=0` as the control — reporting mount → last lane-art line, each lane's own decode cost off its `[timeline] filmstrip/waveform` line, and G7's editor card. It is the rig that says whether the filmstrip half of idea 21 is a real cost or a guess.
