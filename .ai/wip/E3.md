# E3 deadline-paced background work — resume snapshot

## DONE
- The defect was found by reading and then PROVED on prod at default flags: a pre-render claimed by
  `takePrerender` kept the background brake for the rest of its life. The Export button sits inside
  the editor element carrying `onPointerDownCapture={noteEditingActivity}`, so the press that claims
  the job is itself the event that throttles it to `trickle` (20 % duty), renewed by every pointer
  move over the editor while the person watches the dock.
- `core/backgroundWork.ts`: `WorkDeadline` (`background` | `now`), `createJobPace(): JobPace` —
  one pace per job, the broker's answer until `claim()`, `full` after, one-way.
- `core/compose/prerender.ts`: each job owns a `JobPace`; `takePrerender` calls `claim()`;
  both settle handlers `dispose()` (the render has ended by then, so no live job is silenced).
- Tests: 4 new in `backgroundWork.test.ts`, 1 new in `prerender.test.ts`. `npm run typecheck` green,
  `npm test` 1242/1242 green.
- SECOND HALF, also proved on prod first: the timeline's lane art (filmstrip per video channel,
  waveform per audio one) decodes on the same media engine as the at-stop pre-render, which is at
  FULL by then because the editor-ahead window closes two frames after the PREVIEW paints. Fixed by
  making that window refcounted — `holdEditorAhead(what)` returns a release, the preview takes one
  and `useLaneArt` takes another, and the window closes on the last holder.
- Rigs: `scripts/e3-claimpace.mjs` (the claim A/B), `scripts/e3-laneart.mjs` (the filmstrip race).
- Evidence: `docs/qa/e3-claimpace-before.json`, `docs/qa/e3-laneart-before.json`.

## DO NOT
- Do not pace the upload. It is one opaque `supabase.storage.upload()` of a finished file — no
  chunking, no progress events, no media engine — and it is user-initiated, so its deadline is
  already `now`. Idea 21 names it; this codebase has no work there.
- Do not make `claim()` two-way. A claimed job is a user-visible export forever, and a way back
  would be a way to re-brake a render somebody is watching.
- Do not add a switch. `?bgpace=0` already turns the whole brake off and is the positive control;
  U4's rule is that the switch count only goes down.
