# B14 — max records 30 fps, not 60

## DONE
- **VERIFIED on prod, both arms, before any code changed.** The suspicion in TASKS/BACKLOG was right
  about the symptom and incomplete about the cause: TWO different branches of `rateForSurface` refuse
  60 on a 3024x1964 screen, and Robert's 124.8-min take hit the second one.
  - cold (fresh profile, record ~4 s after load): `"…has not been measured yet — holding at 30 fps on
    the old size rule"`, `inout.encoderBudget.v1` absent at the press. UNMEASURED branch.
  - a minute in (meter published): `"…this machine's encoder measured 342 Mpx/s — holding at 30 fps"`.
    MEASURED branch, take recorded `{screen 3024x1964 fps:30}`.
- **CAUSE NAMED AND MEASURED.** `encoderWarm.ts` metered at a hard-coded 1920x1080 with a hard-coded
  `avc1.4D402A` — Main **level 4.2, which cannot be configured above 1080p at all**, so the size was
  not a choice. Mpx/s is NOT a machine constant; it rises with frame size. Same machine, same 40-frame
  meter, the take's own codec ladder, 3 reps each (prod, 2026-09-03):
  `1920x1080 330 · 2560x1440 373/351/280 · 2560x1662 389/394/384 · 3024x1964 398/406/412 · 3840x2160 419/411/417`
  3024x1964@60 wants **356**. Machine gives **~405 at that frame**, 330 at 1080p. The defect is the gap.
- **FIXED (code on this branch, typecheck + 1,178 unit tests green):**
  - `src/core/capture/avcCodecs.ts` (new) — one owner for the AVC profile/level ladder, moved out of
    `rawVideo.worker.ts` (which now imports it) so the meter can be configured at the take's own size.
  - `encoderWarm.ts` — the meter runs at the DISPLAY's own pixel size with the first supported AVC
    candidate; `runMeter()` is now one function instead of two copies of a config.
  - `encoderBudget.ts` — the reading stores the frame it was taken at (`throughputW/H`);
    `measuredEncoderReading()`.
  - `rate.ts` — `rateDecisionForSurface()` returns `{fps, branch, wantMpxPerS, canMpxPerS, measuredAt}`.
    A reading taken at a SMALLER frame than the surface under-states it and may no longer refuse
    (`measured-below-surface`). `rateForSurface` is now a thin wrapper, so the two cannot disagree.
  - `acquire.ts` — the decision goes through the door EITHER WAY: applied when it holds the rate down,
    `ticket.refuse(...)` when it takes nothing, carrying the branch + both numbers into
    `stopStats.decisions`. Console line names the branch.
  - `scripts/fps-check.mjs` — `--armAfterMs=` (leave the page alone before the press) and `--profile=`
    (reuse a Chrome profile, so "cold on a returning machine" is testable). QA only.
